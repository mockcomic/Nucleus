## Design Specificity Verdict

**LLM assessment: strongly authored.** `wheel-core.js` reproduces DESIGN.md's machined-light spec token-for-token: hub stroke accent/0.22, white-at-6% plate edges, 8% lit rim, off-center specular wash at 32%/16%, 3px radial hover nudge on `cubic-bezier(.34,1.56,.64,1)` at 120ms, siblings dimmed to 55%, 0.86→1 pop. Consolas marks the machine seam (`.seg-val`, `.cr-path`, `code`). Theme gallery chips are literal 40px mini wheels from the same `buildWheel`. Lapses into genericness are tone, not visuals: native `confirm()` for quit, unexplained "Ring split" ratio, verbose hint paragraphs.

**Deterministic scan:** 9 findings, 8 unique (one byte-identical duplicate), exit 0. Weave: `dark-glow` on `.brand-dot` is the No-Glow Rule's own authorized exception (real nit: DESIGN.md says "10px brand dot", code has a 14px dot + 10px glow). `bounce-easing` ×2 (`.seg.hovered` wheel.css:37, pop wheel-core.js:213) are false positives by brief — the Snap-Back Rule reserves spring precisely for these. `design-system-color` ×3 on rgba-black shadow alphas (settings.css:94/99/125) is the rule misfiring on shadow tokens; now documented in the `.impeccable/design.json` sidecar. `gpt-thin-border-wide-shadow` on `.modal-card` is borderline FP (12px Y-offset elevation on a floating layer, which the Float-Only Shadow Rule blesses). `em-dash-overuse` (11×) is FP — terse microcopy, committed brand voice. Detector defects: linked-CSS findings mis-attributed to `index.html:0`; duplicate object.

**Visual overlays:** no user-visible overlay (Electron target, no browser automation); fallback signal is grep-verified source attribution.

## Overall Impression

A real system, executed with unusual discipline — spec-to-code fidelity most teams only write in design docs. The aesthetics are nearly done; the trust mechanics aren't. Biggest opportunity: close the lies — two placebo checkboxes that gate nothing, an undo that evaporates after 6 seconds while autosave has already committed, and a native Windows confirm box where the product owns a modal. A wheel that springs perfectly while Settings misreports what it will do undermines the one thing the brand sells: confidence at the cursor.

## What's Working

1. Spec-fidelity as craft: every machined-light value exists in wheel-core.js to the number; shared-renderer rule verifiably honored at all three call sites (`settings.js` import + `miniWheel` + preview, `wheel.js`).
2. The recall-elimination stack: installed-programs combobox (search, ▾, re-scan, `aria-activedescendant`), label-prefilled icon search, per-type `valueHint` placeholders.
3. Peak-end choreography: configure → live preview echoes every edit → "Test the real wheel" closes on the reward object; delete → named undo toast.

## Priority Issues

1. **[P1] Dismiss toggles are placebo.** `#bh-right` / `#bh-esc` render as settings; `wheel.js:78` dismisses on `contextmenu` unconditionally and `windows.js:61` hides on Escape with no `cfg.behavior` check; keys normalized in `config.js`, consumed nowhere. For a muscle-memory product a lying setting is a trust bug and trust is the product. Fix: gate both handlers on `cfg.behavior.*` (config already ships to the overlay). Command: `$impeccable harden`
2. **[P1] Debug instrumentation shipping on the hot path.** Six `/* [DEBUG-TEMP] */` sites in `settings.js` (54–55, 59, 62, 305, 480, 505, 561, 970); `bind()` `JSON.stringify`s preview labels every keystroke; `onConfigChanged` stringifies configs containing base64 payloads. Measurable jank exactly where the user types, plus config leaking to console. Fix: delete the marked block. Command: `$impeccable polish`
3. **[P2] Undo is a 6-second candle; theme-delete has none.** Segment delete toast ttl 6000 while autosave already committed; theme delete confirms with armed "Sure?" then shows "Theme deleted" without an undoFn — while save-as-theme has one. "Configure live, not blind" degrades to "configure live, remember fast." Fix: always attach the clone-snapshot undo (`settings.js:271` pattern); pause ttl on toast hover/focus. Command: `$impeccable harden`
4. **[P2] A power tool with no power path.** No Duplicate; one click per reorder position; no drag; all six editor fields at once; six same-sized glyph mini buttons on the row (the slip-guard CSS comment concedes the mis-click risk). Fix: ⧉ Duplicate in `segRow`, drag-reorder or hold-to-repeat steppers, differentiate Try/Delete icons beyond a 4px margin. Commands: `$impeccable layout`, `$impeccable shape`
5. **[P3] Wheel has zero keyboard/a11y surface; high-stakes chrome leaks to OS.** Overlay SVG: no `role`, no `aria-live`, mouse-only `hitTest`; icon-modal Tab trap queries only `button` (search input leaks focus; no `inert` background); quit is native `confirm()`; no `lang` on either `<html>`. PRODUCT.md scopes AA to Settings — a documented exclusion, not a broken promise — but fix directionally: keyboard summon-and-fire, `inert` background, in-brand armed-button quit. Commands: `$impeccable adapt`, `$impeccable harden`

## Persona Red Flags

**Alex:** glyph-only mini buttons ('Move to other ring' vs 'Try' vs Delete are three near-identical controls with title-only labels); 19 clicks to reposition item 20→1; guarded Play must re-arm for every test firing, no trust hatch; no Duplicate. Abandonment risk while ring-building.

**Jordan:** nothing connects Settings to the wheel except the preview hint + "Test the real wheel" (found only after scrolling); "Ring split 0.2–0.8" is meaningless numbers for the non-config persona; empty-state explains fallback but never says "click + Add"; icon modal opens straight into a network search — offline first-run meets "Search failed" before the offline glyph grid is seen.

**Sam:** icon-modal focus trap excludes `#di-query` and nothing `inert`s the background — the Settings page is readable through the scrim; `.seg-main` is click-only, funneling keyboard users to the 2×7px disclosure disc; 6s toast can strand the only Undo button; the wheel is unusable without a pointer. Keep: roving-tabindex tablist, `:focus-visible` ring, combobox aria, native checkbox switches, computed `--dim` contrast.

**Riley:** duplicate theme names get an unclosed paren ("My theme (2" — `.slice(0, 24)` truncates the closer, `settings.js:741`); modifier-then-Esc dead-ends the hotkey recorder capture listener; gaming-mode app list silently truncates at 64 entries and normalization re-writes hide it; failed persist leaves `dirty` true with no re-armed timer — window sits stale-and-red until the next edit.

## Minor Observations

- `.btn:hover` full-Pilot-Blue 1px border reads near-identical to focus at `.btn.small` scale.
- "Rotation °" 0–359 slider has no ticks; arrow keys are the only precision path.
- `.save-state` sits on `--panel` while DESIGN.md's AA clamp targets the card step.
- `aria-live` on `#save-state` will announce "Saving… Saved" per debounce cycle while typing.
- Reduced-motion and vibrancy fail-sort are genuinely implemented (the two mandates most often skipped).
- Fix the detector's `index.html:0` mis-attribution + duplicate object upstream; don't act on em-dash or rgba-shadow findings in this repo.

## Questions to Consider

1. If the wheel is the hero object with no keyboard path at all, who is the product actually for? A directional/number-key summon-and-fire mode would be both the inclusion fix and a better one-handed power path.
2. Why is a vanishing 6-second toast the entire undo story for the most-used destructive act? A rolling ring of config snapshots in Advanced (import/export plumbing exists) would make "configure live, not blind" true.
3. Should the network be the front door of the icon modal? The offline glyph grid is subordinated by the literal word "Or" — for a product whose promise is fast, is the remote logo the primary affordance or the liability?
