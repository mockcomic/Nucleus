## Overall Impression

The fix round moved the center of gravity from trust to craft: the placebo toggles are gone (A verified every checkbox gates real code — "no placebo switches"), undo is catchable (ttl freezes under pointer and keyboard focus), and the highest-stakes click is finally in-brand. What the run surfaced next is a deeper layer of the same theme: the undo *model* (wholesale graph restore) and the preview *model* (pointer-transparent pane) are now the two places where the interface overpromises what it delivers. The product's promises — "configure live, not blind," one-step-back forgiveness — are 80% honored and the remaining 20% is exactly where users will form (or lose) trust.

## What's Working

1. **The forgiving-action matrix** — every mutation (delete, duplicate, ring-move, theme save/delete, import, reset) takes a snapshot and offers a catchable, focus-freezable 6s undo toast. Best-in-class at this scale.
2. **Shared renderer, obeyed and exploited** — overlay and preview both call buildWheel; miniWheel turns that discipline into self-describing theme chips.
3. **Reorder craft** — holdRepeat steps by item identity with a window-level pointerup because touch() rebuilds the row under the finger; a detail most teams get wrong.
4. **DESIGN.md conformance verified clean** — no-glow held to the dot, float-only shadows observed, accent-deep AA discipline intact, radii in spec, reduced-motion and reduced-transparency both genuinely implemented, modal trap/Esc/scrim/focus-return/inert complete.

## Priority Issues

1. **[P1] Snapshot-restore undo destroys later edits.** `cfg = snapshot` on delete/duplicate/ring-move undo: undo a delete after any later edit and the unrelated work reverts silently. Fix: store the inverse op (splice back at captured index / remove the duplicated id); if graph restore stays, detect drift and warn "this reverts all changes since." Command: `$impeccable harden`
2. **[P1] "Edits are watched live" is a promise the code breaks.** `onConfigChanged` drops external config.json edits while `dirty` (mid-typing or mid-slider-drag), then persist last-writer-wins clobbers them — silent data loss in both directions. Fix: queue the external change; on persist, compare store revision and offer an in-brand "config changed on disk — Reload / Keep mine" choice. Command: `$impeccable harden`
3. **[P2] The live preview is inert where it matters.** `#wheel-preview svg { pointer-events:none }` hides the hover nudge, the 55% dim, and the hub report — the signature states a configure-live pane exists to show; buildWheel already returns hitTest/setHover. Fix: wire preview hover through hitTest; keep pop and click-firing suppressed via the existing preview opt. Command: `$impeccable animate` (or harden)
4. **[P2] Segment row: seven icon-only buttons, two of them duplicates-in-disguise.** Row now carries disclosure + 4 transport + Try + Delete; "Move to other ring" repeats the editor's Ring radio; aria-labels read pointer advice aloud ("hold to keep moving"). Fix: row keeps 4 controls (↑/↓/Try/Delete + disclosure); fold ring-move and Duplicate into the editor; fix the SR labels. Command: `$impeccable layout`
5. **[P2] Icon picker is a wall with a network dependency on open.** Auto-fired dashboardicons search means offline first-run opens on "Search failed — check the connection"; 57 glyph cells with near-duplicate names underneath. Fix: don't auto-search; curated ~12-glyph row + search field, full grid on demand; dedupe catalog names. Command: `$impeccable onboard`

## Minor Observations

- Action-types card omits `file`; the `app` description over-promises it.
- `.di-subhead` = second uppercase-tracked label; non-error toast border should be hairline (accent is reserved for action invitations); `.theme-name-input` padding off the 7×9 token; blur-commits an empty theme name as the placeholder-derived title.

## Questions to Consider

1. PRODUCT.md principle 4 is "Configure live, not blind" — so why is the pane built to sell that promise pointer-transparent? If the preview can't hover, spring, or report through the hub, is it a live preview or a swatch box?
2. The hero object is pointer-only end to end. Who is the wheel actually for — and does Settings's (genuinely good) keyboard hygiene accidentally stand in for an accessibility story the wheel needs for itself?
3. If "it has to feel touched" is a core principle, why does the place where mastery is built — the segment row — read like a generic toolbar of anonymous glyphs?
